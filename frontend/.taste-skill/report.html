CPC Vote · Election desk

A dashboard redesign for school election administrators: status and participation lead, course detail and candidate results follow. The blue/yellow wordmark is retained; the existing self-hosted Plus Jakarta Sans font, neutral surfaces and semantic status colours form the interface.

Scope: /admin/dashboard and its opt-in navigation appearance. Other admin screens retain their current navigation and styling. APIs, polling, types, calculations, session behaviour, permissions, backend and election records were not edited.

What changed

  • Replaced the campus-image hero and unscheduled zero countdown with the election’s actual name, status and schedule.
  • Moved eligible voters, ballots cast, voters remaining and candidate count into compact linked summary cells.
  • Displayed the existing turnout percentage with a labelled participation ring and full course counts/percentages in a readable table.
  • Retained candidate support calculation and clarified its label: ballots selecting a candidate, rather than a probability of winning. Candidate vote counts use the existing API field.
  • Added explicit no-candidate, no-course, no-eligible-voter, loading and error presentations; failed updates retain the last actual response with a notice.
  • Added a keyboard skip link and opt-in mobile drawer focus containment, Escape/backdrop closure, focus restoration and background scroll locking. No animation is needed; reduced motion is respected.

Real data at capture: draft election, 4 eligible voters, 0 ballots cast, 4 not yet voted, 0% turnout, no candidates. All before/after dashboard captures use this same real election.

Limitations and skill mismatch

.agents/skills/design-taste-frontend/SKILL.md is an older single-file installation and contains no scripts or app-screen reference. C:/Users/ED/.agents/skills/design-taste-frontend includes draw.mjs, inspect.mjs and lint.mjs, but no references/app-screens.md and no --app support. Its documented target excludes dashboards. User-authorized app-appropriate fallback: subject/data audit, explicitly chosen compact Election desk direction, authenticated Playwright screenshots and DOM measurements at 1440/768/390, screenshot critique and fix loop. No landing-page direction was dealt or reproduced. No frontend/design images were used.

Ran the available source scanner before and after. It does not pass: it applies landing-page rules to application surfaces, flags box-shadow: none as shadows, flags structural sidebar/table-summary dividers, and warns about the existing self-hosted font and outlined panels. These are recorded in source-lint.json, not treated as an app-screen approval. App inspection was performed with equivalent browser checks instead.

  • Real election is draft with zero ballots and no candidates. Active/closed, nonzero-turnout, populated candidate rows and zero-eligible states cannot be exercised with current data without modifying records or using fixtures. Neither was done.
  • Browser viewport emulation is not physical-device or screen-reader testing.
  • Installed Taste has no app-screen reference or --app script support. Equivalent authenticated Playwright inspection used.

Database services were initially stopped. Docker Desktop was started and the existing backend containers resumed; no migrations, seeders, candidate changes, votes or election controls were run. Verification sent no election-record mutation requests.
